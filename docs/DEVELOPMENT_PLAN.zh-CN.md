# 爬梯与自由滑翔 Demo 开发计划

> 本文件维护产品决策与里程碑定义。当前实施与验收状态以 [STATE](STATE.zh-CN.md) 为准。

更新：2026-11-07。已从可行性讨论进入开发。用途为个人娱乐、演示和可能的自媒体内容；不以商业发行作为首轮目标。免费工具和素材优先，付费项目按具体效率与体验收益另行讨论。

## 已确定的产品与平台

- Unity 6.3 LTS、Windows 桌面和 Quest Pro PC VR；Quest 独立运行是后续候选。
- 核心流程：交替拉动爬梯 → 抵达平台 → 继续爬或选择起飞 → 自由滑翔 → 降落。
- 一座简化塔、多个平台、小范围地形和几个落点；先完成循环，再提升画面。
- 支持直接进入飞行试验场，避免调参时反复爬梯。
- 平台最终希望使用明显的虚拟按钮和手势；PC VR 路径的手势可用性尚待实际验证。

## 本轮梯子决策

用户实测发现：以微小绳长变化的正负直接切换重/轻阻力会快速震颤；突然变轻会诱发再次拉出，且小于一厘米的变化可能不可靠。

首轮仅要求左右手交替完成明显拉动就向上爬，停止交替就停止上升。重复单侧拉动和同时拉动不获得额外攀爬优势。不做精准抓点映射，也不要求判定真实松手、滑落或力竭。游戏不根据绳速符号发送阻力变化。

最初实现用可调的有效拉出行程、回程重新准备行程及交替规则过滤抖动。5 cm 拉出、3 cm 回程和每次 0.25 m 虚拟上升仅为离线软件默认值，必须根据记录和体感再标定。游戏内可视高度按事件递增，先不追求连续精确位移映射。

稳定阻力是首轮实机候选。设备原生向心模式可能在以后提供拉出重、回程略轻的感觉。用户提出回程可能需要保持约四分之三拉出负荷；这不是已核实的参数编码或百分比定义，本轮不配置硬件。

## 架构与协作

游戏进程包含独立的输入、梯子、飞行、流程、画面和目标阻力模块。未来的本地 PUMP 服务独占 BLE、处理数据新鲜度及受控请求。模拟和回放是同一接口的输入来源；不会用游戏脚本自动完成现有控制台的逐条人工授权。

首轮由集成者与设备/环境、飞行、XR/表现等职责分工；具体文件归属见根目录 AGENTS.md。同一场景、包清单、项目设置和公共契约只有一名写入负责人。飞行动力学在游戏进程内计算，不拆成网络微服务。

## 里程碑与验收

| 阶段 | 交付 | 验收 |
|---|---|---|
| M0 | 文档、接口、目录与版本 | 确定 Unity 补丁与包；可重建环境，注明未完成项 |
| M1 | 桌面/PC VR 工程外壳、模拟左右输入、试验场 | Unity 真正导入、无编译错误，桌面程序运行；Quest Link 现场确认视角与帧时间 |
| M2 | 正常飞行核心、空中测试入口、落地与重置 | 离线数值检查和 Unity 内实际运行均通过；头部观察不改变飞行输入 |
| M3 | 真实绳长与稳定负荷 | 左右映射和拉程标定，断流不新增动作；人体操作另设集中窗口 |
| M4 | 渐进阻力 | 单独验证连续调阻、时序和实际手感；原生模式与软件目标曲线分别评估 |
| M5 | 梯子、平台、飞行完整循环 | 平台操作不误触转向；真实使用可玩完一轮 |
| M6 | 体验优化与Windows包 | 帧时间、音效、清楚提示、可重复试玩；脱离编辑器可运行 |

M1/M2 代码与离线检查可以先进行；Unity 编辑器、许可证登录和头显执行是独立验收，不以源码存在代替。具体完成情况维护在 README 和 SETUP 中。

## 当前不确定项及处理

1. 双台连续调阻质量：后置至 M4，不阻塞离线飞行与简化爬梯。
2. 梯子阈值与顺手程度：参数化，通过动作记录和试玩调整。
3. 飞行真实性：先正常滑翔、共同刹车和差动转弯，再依据资料与体验修正；不把简化模型宣传为专业训练模拟。
4. PC VR 手势：在 Link 上实测；当前模拟按键只用于开发，不能算手势交互验收。
5. 付费资源：遇到具体收益再讨论，不预购大型插件或素材包。

## 工具与素材

Unity Hub、选定的 Unity 6.3 LTS 编辑器、Windows 构建组件、OpenXR 相关正式包和 Meta Horizon Link 构成预期环境。离线 C# 核心检查使用仓库私有的微软 .NET SDK。工具下载和实际配置见 SETUP；不将下载完成视为安装或登录完成。

首轮场景由基本几何生成。后续只补必要天空、地面和音效，记录素材来源和许可。保留原始 PUMP 实测证据在 C:/projects/power，本工程不搬动原始记录。
