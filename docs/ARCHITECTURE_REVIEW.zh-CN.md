# A2 后的架构与开发效率复盘

日期：2026-11-07。结论：保留当前分层，先解决文档和复现问题，不做全面重写。

## 已有效的结构

`合成输入 → DemoSession → LadderModel / FlightModel → Unity 表现`

- 核心不依赖 UnityEngine，离线检查快；表现层和自动玩家共用流程，减少“两套游戏规则”。
- `ValleyCourse` 为渲染、AGL、碰撞提供同一高度场，已修复三角形插值不一致。
- Unity CLI 负责原生构建，真实 Player 负责逐帧记录和截图。离线通过与实际画面通过分开记录。
- 运行时物理仍在进程内。未来只有设备桥接具有独立服务的理由；多 agent 是开发组织方式，不是拆微服务的理由。

## 建议的迭代门槛

1. 核心规则变化：先 `test-core.ps1`；流程变化再加 `-Trial`。
2. Unity 表现或场景变化：CLI 构建后运行 A2；只修改文档不重复构建与长回放。
3. 同一构建测试第二路线可用 `-SkipBuild`；它验证已有二进制，不能证明工作树已经构建。
4. 审查实际截图，不能仅以截图文件存在作为视觉验收。
5. 日志和构建产物留在 `artifacts/`；公开报告保留结果、边界、运行编号，避免发布含本机路径或授权信息的原始日志。

多人/多 agent 并行时按 AGENTS 文件归属拆任务；集成者串行更改公共契约与包清单，串行运行 Unity Editor。当前项目规模不需要额外网络服务、数据库、付费资产或复杂构建平台。
